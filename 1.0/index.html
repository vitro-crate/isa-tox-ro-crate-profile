Overview

This profile extends the ISA RO-Crate profile (ISA RO-Crate Profile, originally produced by NFDI4Plants) with the entity types needed to describe experimental in vitro toxicology studies and New Approach Methodologies (NAMs).

RO-Crate provides a portable data package expressed in Schema.org terms. The ISA profile defines the Investigation → Study → Assay hierarchy and represents experimental steps as Bioschemas LabProcess and LabProtocol entities. This profile specifies the toxicological requirements and the ontology terms used to express them.

Chemical entities are represented as MolecularEntity instances, biological materials as Sample entities classified by sampleType, and experimental steps as LabProcess entities classified by the intendedUse of the protocol record they execute: TestSystemPreparation, Exposure, EndpointReadout or DataAnalysis. A step whose protocol record declares none of these four terms is validated against the base and ISA layers only; a term outside this set is reported as a warning.

Requirement levels follow RFC 2119.

Conformance

A crate following this profile declares conformance using the RO-Crate 1.2 convention: the RO-Crate Metadata Descriptor's conformsTo carries only the single base-specification URI, while the profile URIs the crate targets are declared on the Root Data Entity (./). Each referenced profile is also declared as a Profile contextual entity.

{
  "@id": "ro-crate-metadata.json",
  "@type": "CreativeWork",
  "conformsTo": {"@id": "https://w3id.org/ro/crate/1.2"},
  "about": {"@id": "./"}
}

The Root Data Entity declares the targeted profiles:

{
  "@id": "./",
  "@type": "Dataset",
  "conformsTo": [
    {"@id": "https://github.com/nfdi4plants/isa-ro-crate-profile"},
    {"@id": "https://w3id.org/ro/crate/isa-tox/1.0"}
  ]
}

No w3id.org/ro/crate/isa/… permalink has been registered; the ISA layer is therefore identified by the IRI the profile extends. Both referenced profiles are declared as contextual entities:

{
  "@id": "https://github.com/nfdi4plants/isa-ro-crate-profile",
  "@type": ["CreativeWork", "Profile"],
  "name": "ISA RO-Crate Profile"
},
{
  "@id": "https://w3id.org/ro/crate/isa-tox/1.0",
  "@type": ["CreativeWork", "Profile"],
  "name": "ISA-Tox RO-Crate Profile",
  "version": "0.1.0-draft.1"
}

Note on RO-Crate 1.2 placement: RO-Crate 1.2 recommends declaring the profiles a crate targets on the Root Data Entity (./) and reserving the Metadata Descriptor's conformsTo for a single base-specification value — which this profile follows.

A machine-readable Profile Crate bundling this description with the SHACL shapes MAY additionally be published at the profile URI; this is planned but not yet provided.

Requirements

An Investigation MUST include at least one Exposure referenced by one of its Studies or Assays. A crate that records no exposure of a test system to a chemical does not describe an in vitro toxicological experiment.

Study - Adverse Outcome Pathway

Is based on the ISA Study. A study should address one Adverse Outcome Pathway via schema:mentions; its assays annotate the Key Events (Assay - Key Event). The referenced node is the AOP-Wiki entity: @id is https://identifiers.org/aop/<id>, typed AdverseOutcomePathway (AOPO) and DefinedTerm, with the wiki page as url. A crate MAY carry the surrounding subgraph: Key Events (aop.events/<id>) and KeyEventRelationship nodes (aop.relationships/<id>) cross-linked by upstream_event and downstream_event. The adverse outcome is reached through the pathway's has_adverse_outcome, not named on the Study.

The following rows are those of the ISA Study, reproduced with the requirement levels this profile assigns. mentions is introduced by this profile.

additionalType MUST Text or URL 'Study' or ontology term to identify it as a Study. It is what selects the entity, so no shape can check it.
identifier MUST Text or URL Identifying descriptor of the study.
name MUST Text A title of the study.
mentions SHOULD DefinedTerm The Adverse Outcome Pathway the study addresses, as its AOP-Wiki node.

Is based on the ISA Assay. An assay measures one endpoint and names the KeyEvent it reads out via schema:mentions: @id is https://identifiers.org/aop.events/<id>, typed KeyEvent (AOPO) and DefinedTerm. What it measures is named in BAO terms through measurementMethod and measurementTechnique.

MolecularEntity - Test and Control Chemicals

Test and control chemicals are represented as MolecularEntity instances, each denoting a single defined molecule and bearing the structural properties specified below. Schema.org's ChemicalSubstance defines no structural property and is not used. Test items that are mixtures are outside the scope of this version.

Concentration is not a property of the compound. It is recorded per well in the Exposure's condition table.

Property Required Expected Type Description
@id MUST Text or URL SHOULD be an absolute, resolvable compound IRI — a PubChem, CompTox or CompoundWiki entry. A crate-local identifier (#iopanoic-acid) is allowed, and is the only option for a coded or proprietary test item with no public record; the compound's identity is carried by inChIKey and identifier either way.
@type MUST bioschemas.org/MolecularEntity —
name MUST Text The compound name.
identifier SHOULD Text, URL or schema.org/PropertyValue A compound identifier (e.g. InChIKey, CAS, PubChem CID), ideally a PropertyValue carrying its scheme, resolving to an authoritative resource.
inChIKey SHOULD Text The hashed InChI for unambiguous structure lookup.
smiles SHOULD Text The compound structure as SMILES.
inChI MAY Text The compound structure as InChI.
molecularFormula MAY Text The molecular formula.
url MAY URL Link to an external record, e.g. PubChem, ChEBI or CompoundWiki.

Sample - Source Cells

Based on the Bioschemas Sample type (ISA Sample). Source cells are the material from which a Test System Preparation proceeds. The sampleType property classifies the material. Cell lines and primary cells carry the additional requirements specified below; materials of any other kind are governed by this section alone. A Sample consumed by a preparation step is source cells irrespective of its declared sampleType. The values "CellLine" and "PrimaryCell" in additionalType are retained as aliases.

Samples are typed as both Sample and BioSample, a Bioschemas subtype of Sample. Validation is performed against Sample; a BioSample-aware consumer may read cellType, anatomicalStructure and sex directly. These three properties express the same assertions as the corresponding Characteristic PropertyValue items against which conformance is determined, and are therefore optional.

Property Required Expected Type Description
@id MUST Text or URL Could be the unique sample name.
@type MUST BioSample, a Bioschemas subtype of bioschemas.org/Sample The array ["BioSample", "Sample"], most specific first. Sample MUST stay in it: every requirement here is matched on that type.
sampleType MUST schema.org/DefinedTerm A categorical annotation of the material as a fixed, resolvable ontology term; see the expected terms below.
cellType MAY Text, URL or schema.org/DefinedTerm BioSample: the cell line, lineage or biological classification of a cell. Also carried as a cell-type Characteristic (EFO:0000324), which is what the shapes check.
anatomicalStructure MAY schema.org/AnatomicalStructure, DefinedTerm or URL BioSample: the organ or tissue the material was collected from. Also carried as Organ / Tissue Characteristics (UBERON:0000062, UBERON:0000479).
name MUST Text A name identifying the sample, e.g. the cell-line name.
additionalProperty SHOULD schema.org/PropertyValue (Characteristic) Characteristics of the sample, e.g. passage number or growth conditions.

Expected sampleType terms: Each is a DefinedTerm whose @id dereferences to the term. The sections below are selected by this term. A material whose kind has no corresponding term in this table is reported, which also detects a malformed sampleType.

Sample - Test System

The test system a Test System Preparation produces from its Source Cells. Its sampleType is "cell culture" → OBI:0001876.

Property Required Expected Type Description
@id MUST Text or URL Could be the unique sample name.
@type MUST BioSample, a Bioschemas subtype of bioschemas.org/Sample The array ["BioSample", "Sample"], most specific first. Sample MUST stay in it: every requirement here is matched on that type.
name MUST Text A name identifying the material, e.g. "SK-N-AS, 48 h culture".
additionalProperty SHOULD schema.org/PropertyValue (Characteristic) Characteristics of the material, e.g. passage number or growth conditions.
sampleType MAY schema.org/DefinedTerm "cell culture" → OBI:0001876. The term is what makes the Sample a test system: without it these requirements do not apply to it.
isBasedOn SHOULD Sample The material this one was grown from — the source cells for a test system, the test system for the exposed material. See the modelling rules below.

Modelling rules:

  • A test system derives from at most one parent Sample. Culture each source separately, or type material grown from several sources as a co-culture.

Sample - Exposed Test System

The test system following application of the chemical. It carries the requirements of the Test System and declares isBasedOn the test system from which it was exposed, and so has no table of its own. The exposed material is identified by the step rather than by the Sample: an Exposure MUST declare the test system as schema:object and the exposed material as schema:result. Traversing isBasedOn in reverse yields the derivation chain: exposed test system → test system → source cells.

LabProcess - Test System Preparation

A LabProcess that prepares the biological model from its source cells, including its maintenance in culture, typed by the intendedUse of its protocol record, a term of the preparation types set below. A test system may be prepared in several steps. A stably modified line constitutes the source material itself and is not represented as a preparation step.

The three terms below form a DefinedTermSet identified by https://w3id.org/ro/crate/isa-tox/1.0/preparation-types and defined in this profile's vocabulary, shapes/ontology.ttl. A step is recognised as a test system preparation when the intendedUse of its protocol record declares that set with inDefinedTermSet:

Preparation type Term
Culture, plating EFO:0003789 growth protocol
Transient transfection OBI:0001152 transfection
Differentiation GO:0030154 cell differentiation
Property Required Expected Type Description
@id MUST Text or URL Could identify the process using the process name and protocol reference.
@type MUST bioschemas.org/LabProcess —
name MUST Text The name of the process, e.g. "Cell Culture".
object MUST bioschemas.org/Sample The input source sample(s): a cell line or primary cells. At least one.
result MUST bioschemas.org/Sample The output (cultured) sample(s). At least one.
parameterValue MUST schema.org/PropertyValue (Parameter) Process parameter(s); see expected values below. At least one.
executesLabProtocol MUST bioschemas.org/LabProtocol The step's protocol record: exactly one (SHOULD).

Expected parameterValue items: Each is a Parameter PropertyValue (additionalType "ParameterValue"). At least one parameterValue is required. The following are recommended for this step:

name Required propertyID
Culture Medium SHOULD http://www.bioassayontology.org/bao#BAO_0000114

LabProcess - Exposure

A LabProcess that exposes the test system to one or more chemicals, typed by the intendedUse of its protocol record, treatment protocol (EFO:0003969). It declares the cultured Sample as object, executes a protocol record naming the compounds applied, and declares the exposed Sample(s) as result.

The experimental design is recorded in a condition table (CSVW): a data file about those exposed Samples, with one row per well giving cell line, compound, concentration and exposure duration.

Property Required Expected Type Description
@id MUST Text or URL Could identify the process using the process name and protocol reference.
@type MUST bioschemas.org/LabProcess —
name MUST Text The name of the process, e.g. "Exposure".
object MUST bioschemas.org/Sample or File The input cell sample(s) being exposed. At least one. (A MolecularEntity is not allowed here — see note above.)
parameterValue MUST schema.org/PropertyValue (Parameter) Exposure parameter(s); see expected values below. At least one.
result MUST bioschemas.org/Sample or File The exposed sample(s) the step produces. At least one. The condition table is not a result: it is a File + csvw:Table about the exposed Samples, and each exposure SHOULD have one.
executesLabProtocol MUST bioschemas.org/LabProtocol The step's protocol record: exactly one (SHOULD), whose reagents MUST include at least one test or control compound (a MolecularEntity).

Expected parameterValue items: Each is a Parameter PropertyValue (additionalType "ParameterValue"). At least one parameterValue is required. The following are recommended for this step:

name Required propertyID
Exposure Duration SHOULD http://purl.obolibrary.org/obo/NCIT_C83280
Cell Seeding Density SHOULD http://purl.obolibrary.org/obo/MSIO_0000062
Microplate SHOULD http://purl.obolibrary.org/obo/NCIT_C43377

LabProtocol - Protocol record

Based on the Bioschemas LabProtocol type (ISA LabProtocol). Each LabProcess executes exactly one protocol record. The record is present whether or not a document was deposited, since its intendedUse determines the type of the step. A deposited standard operating procedure is a File additionally typed LabProtocol, referenced by the record through isBasedOn; one document may therefore serve several steps. ISA-JSON defines no isBasedOn on a protocol, and this reference is consequently lost on conversion.

Property Required Expected Type Description
@id MUST Text or URL One record per step, e.g. the process @id followed by _protocol.
@type MUST bioschemas.org/LabProtocol —
intendedUse SHOULD schema.org/DefinedTerm The protocol type of its step, from the table below, written as {"@id": …} and described once in the graph.
name SHOULD Text The name of the protocol, e.g. "Exposure protocol".
description SHOULD Text What the lab stated about the procedure; a builder writes none of its own.
url MAY URL Where the lab published the procedure, when it stated one.
reagent MAY bioschemas.org/MolecularEntity The compounds the protocol applied. On the Exposure's record this is a MUST: the test and control compounds, at least one, checked on the Exposure step.
isBasedOn MAY File The deposited documents the step follows.
Step intendedUse
Test System Preparation a term of the test system preparation types set
Exposure EFO:0003969 treatment protocol
Endpoint Readout BAO:0000523 assay protocol
Data Analysis OBI:0200000 data transformation: no protocol-type term exists, so the OBI process class stands in, as ISA's reference dataset BII-I-1 does for extraction

Example ro-crate-metadata.json

A conforming crate types every step by the intendedUse of its protocol record and every source material by its sampleType, and validates in three passes: base RO-Crate 1.2, ISA, then ISA-Tox.
